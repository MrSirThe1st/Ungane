# ADR-003: Env keys, safe errors, and deferred admin surface

- Status: Accepted
- Date: 2026-07-30
- Owners: Admin (platform owner)

## Context

Need clean secrets handling, safe UI errors, Zod at write boundaries, and a clear stance on platform admin vs business app — without building admin UI early.

## Decision

### Environment

- Local secrets live in **`.env`** at the repo root (gitignored). No `.env.example` in repo.
- Required vars are documented in `docs/context/tech.md` and `config/env.ts`.
- **Never hardcode** URLs, keys, or provider secrets.
- Use **new Supabase API keys**:
  - `NEXT_PUBLIC_SUPABASE_URL`
  - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (`sb_publishable_...`) — browser + user-scoped server
  - `SUPABASE_SECRET_KEY` (`sb_secret_...`) — server-only admin client (bypasses RLS)
- WhatsApp: `WHATSAPP_API_KEY` (required when provider is not `stub`)

### Error handling

- Log real errors with `logError` / `console.error` internally.
- Return **safe** French messages to the UI via `ApiResult` / `SafeError`.
- Never leak raw DB, Supabase, or provider errors to clients.
- Prefer `withSafeResult` / `failureResult` from `lib/errors.ts` at server boundaries.

### Validation

- Zod is mandatory before DB inserts/updates (`lib/validations/*`).
- Starter schemas: customer create/update, campaign create.

### Platform admin vs business users

- **Business app** = current `app/(app)/*` (owners + staff).
- **Platform admin** = deferred; **no admin routes in this repo yet**.
- Future direction: **separate subdomain** (not `/admin` in the business app). Document only until requested.

## Consequences

- Positive: secrets stay out of git; debugging stays possible; admin won’t pollute MVP UX
- Negative: new clones must copy env var names from docs manually
- Neutral: legacy `anon` / `service_role` keys are not used

## Validation

- `.env*` gitignored; no `.env.example`
- Clients use publishable/secret helpers from `config/env.ts`
- Agent rules ban hardcoded secrets and raw error leakage
- Supabase Data API + automatic RLS assumed; every new table ships with policies
