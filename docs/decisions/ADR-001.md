# ADR-001: Single Next.js App + Project Blueprint

- Status: Accepted
- Date: 2026-07-29
- Owners: Admin (platform owner)

## Context

UNGANE is starting from scratch as a WhatsApp-first CRM for Congo / Africa. Without upfront constraints, the codebase risks:

- Premature monorepo complexity
- Direct coupling to 360dialog
- Weak multi-tenant isolation
- Inconsistent auth and API contracts
- Agents working from a 2,000+ line README instead of focused docs

## Decision

1. **Single Next.js application** for MVP — flat routes (`/dashboard`, `/customers`, `/conversations`, `/campaigns`, `/settings`). No monorepo.
2. **Project blueprint** as agent operating system:
   - `docs/context/project-context.md` — concise product truth (root stub points here)
   - `project-updates.md` — append-only change log (read first)
   - `docs/context/*` — vision, product, tech, design, roles
   - `docs/features/*` — implementation-oriented specs
   - `docs/blueprint/ai/AGENT_RULES.md` — coding standards
3. **Supabase** for Auth, PostgreSQL, and Realtime
4. **MessagingService abstraction** over Meta WhatsApp Cloud API (provider-swappable; `stub` for local)
5. **Phone + OTP primary auth**; email + password secondary
6. **TypeScript strict** + Zod at boundaries + shared `ApiResult<T>`
7. **Multi-tenant** via `business_id` on all business data

## Consequences

- Positive:
  - Fast MVP velocity
  - Clear agent entry points
  - Provider independence for WhatsApp
  - Security defaults (server authz, tenant scope)
- Negative:
  - May need to split packages later if mobile or multiple apps appear
  - Discipline required to keep `lib/whatsapp` as the only provider boundary
- Neutral:
  - Hhousing monorepo docs archived under `docs/archive/hhousing/`

## Alternatives Considered

1. **Monorepo with apps/packages** — better long-term separation, too heavy for current team/speed goals
2. **Ad-hoc docs only in README** — too large for agents; high drift risk

## Rollout Plan

- Step 1: Adapt docs blueprint (this ADR + context/features) — done as Phase 0
- Step 2: Scaffold Next.js app with flat routes and `lib/supabase`, `lib/whatsapp`
- Step 3: Auth + business + WhatsApp connection
- Step 4: Customers + conversations MVP demo

## Validation

- Agents read `project-updates.md` then `project-context.md` before coding
- No monorepo tooling introduced without a new ADR
- Provider calls only through MessagingService
- Tenant isolation reviewed on every data-access change
